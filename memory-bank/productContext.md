# Product Context Template

> **Purpose:** The "why" behind the project. Explains the problem being solved, who the users are, and what features the product will offer.

---

## Problem Statement

```
[Describe the core problem this project solves. Be specific and concise —
 ideally one or two paragraphs.

 Example:
 "Online retailers struggle with fragmented order management systems that
 don't integrate with payment processors or shipping providers. This leads to
 manual data entry, delayed order fulfillment, and poor visibility into
 inventory status. As a result, customer satisfaction drops and operational
 costs increase."]
```

---

## User Personas

```
[Define 1–3 key user personas.

 Format:
 Name: [Persona Name]
 Role: [Job title / role]
 Goals: [What they want to achieve]
 Pain Points: [What gets in their way]
 Tech Savviness: [Beginner / Intermediate / Advanced]

 Example:
 Name: Sarah, E-commerce Manager
 Role: Operations lead at an online retailer
 Goals: Monitor order status, identify bottlenecks, reduce manual work
 Pain Points: Scattered dashboards, delayed data sync, no real-time alerts
 Tech Savviness: Intermediate
]
```

---

## User Stories

```
[List key user stories using the "As a [role], I want to [feature] so that [benefit]" format.

 Example:
 - As a customer, I want to track my order in real time so that I know when to expect delivery.
 - As an admin, I want to view all pending orders in a single dashboard so that I can prioritize fulfillment.
 - As a warehouse operator, I want to scan orders for shipping so that packages are sent without errors.
 - As a support agent, I want to look up order history so that I can resolve customer inquiries quickly.
]
```
